# 宣传片制作脚本

改了界面以后，重新生成宣传片：

```
node make.mjs 编排_演奏版.js out/演奏版            # 默认用 ../../play.html
node make.mjs 编排_演奏版.js out/演奏版 某个页面.html
```

产出：`out/演奏版.mp4`、`out/演奏版.检查报告.md`。报告里有一项是 ✗，命令就以失败退出。

引导视频（8 步引导从头走到尾）：

```
node make_guide.mjs 编排_引导.js out/引导视频
```

它的编排直接写「手每一刻在哪」（秒），因为要配合引导一步步走；检查项是：无卡顿、8 步走完、每个起音音高对、最后切到柔和、第一个音的声画差 ±40ms。

## 三个文件各管什么

- **编排_xxx.js** —— 只写音乐：几拍、哪一小节进几档、什么时候换音色、旋律的简谱和拍数。换曲子、改结构只改这里。
- **hands.js** —— 把编排换算成两只手每一刻的位置。坐标全部问页面要（`GI.layout`），界面改了不用改这里。
- **make.mjs** —— 两遍录制 + 合成 + 检查。

## 依赖

- 页面要 v47 及以后：有 `GI` 接口（时钟、预备拍、干净画面、坐标）。
- Node 22、Playwright 自带的 Chromium、ffmpeg。在 Claude 的云端环境里是现成的；本机没有验证过。
- 一次大约 3–4 分钟（55 秒的片子）。

## 自动检查哪些

| 项 | 标准 |
|---|---|
| 录制卡顿 | 第一遍里两次读手之间不超过 90ms；卡了自动重录，最多 3 次 |
| 起音 | 每个该起的音都响了、音高对、和拍子差 ≤150ms（报告里给最大差值） |
| 滑音 | 每个音持续段的中点，实际音高落在这个音上 |
| 换档 | 落在该在的那一拍上，±0.1 秒 |
| 速度 | 全程不变 |
| 音色 | 该换的时候换到了 |
| 声画同步 | 在成片上量预备拍第一下：声音起点 vs 数字出现那一帧，±40ms |

## 换了交互以后可能要重新标定的

这些常数写在 hands.js 开头，是实测出来的，不是从代码推的。检查报告会暴露它们失效，但不会自动修：

- 换档要在拍前 0.5 秒挪到位
- 捏合提前 0.06 秒
- 八分音符捏 0.15 秒、松 0.15 秒
- 声音整体后移 15ms（make.mjs 里的 `AV_OFFSET`）
