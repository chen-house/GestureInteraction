# 手势乐器

摄像头 + 手势 = 一把能演奏的乐器。右手是特雷门琴（音高 / 音量 / 捏合起音），左手是桑巴打击乐（档位 / 速度 / 音色转盘）。

**这是乐器，不是装置。** 验收标准只有一条：录下来，关掉画面，只听。

## 怎么跑

摄像头权限必须走 `http://localhost` 或 `https://`，`file://` 直接双击打不开。

```bash
双击 启动.command
```

它会在本目录起一个 Python 服务器（端口 4173）并打开 `play.html`。

## 操作

**右手（画面右侧）**

| 动作 | 作用 |
|---|---|
| 上下移动 | 音高（屏幕上有音阶线） |
| 左右移动 | 音量，两端各有一块平台，左端是真的 0 |
| 拇指捏食指 | 起音。松开收音。连续两个同音（`3 3`）靠它 |

**左手（画面左侧）**

| 动作 | 作用 |
|---|---|
| 上下移动 | 打击乐档位，6 档，累积编制。抬手选、放手保持 |
| 左右移动 | 打击乐音量 |
| 拇指张合 | 速度，80~140 BPM |
| 握拳 | 弹出音色转盘，往四个方向推：手碟 / 柔和 / 木琴 / 玻璃。推到哪个就试听哪个，松手定下 |
| 把手移出画面 | 任何时候的退出方式（不依赖阈值，必然成立） |

按 `D` 看诊断面板：识别帧率、各个手势的实时读数、加载来源。

## 文件

| 路径 | 是什么 |
|---|---|
| `play.html` | 当前版本，`启动.command` 打开的就是它 |
| `play-GOOD-v26.html` | 当前这个已验证可用的版本的存档 |
| `play-v*.html` | 历史版本，每一版都是独立可运行的单文件 |
| `Claude outputs/selftest-v*.py` | 每一版的自测。把页面的 module 抽出来配浏览器桩在 node 里真跑一遍 |
| `lib/` | MediaPipe 识别库（本地，不联网）。`./lib` 是相对页面所在目录的，所以页面必须放在这一级 |
| `theremin.html` `samba.html` `step1.html` | 早期单项实验 |

## 自测

```bash
python3 Claude\ outputs/selftest-v26.py play-v26.html
```

191 项。另外要扫帧率：画面与识别之比 1:1 / 1:2 / 1:4 / 1:6，识别间隔 33 / 66 / 100ms。**很多坑只在低帧率或高刷新率下出现**，1:2 + 30fps 全过不代表没问题。

## 设计记录

交互上踩过的每一个坑都按规则记在 Claude Project 的 `claude/interaction-lessons.md` 里（26 条）。设计新手势前先过一遍。最贵的三条：

1. 手只负责「改变」，系统负责「保持」——不要让手一直举着维持一个状态。
2. 数帧只能数识别帧，不能数画面帧——两者差 2~10 倍，且比例随显示器变。
3. 不要把手的静息位置变成一次选择——人不操作的时候手就是垂下来的。
